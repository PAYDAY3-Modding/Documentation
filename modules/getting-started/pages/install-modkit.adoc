= Install the Modkit

The modkit contains the PAYDAY 3 development project and the tooling used to author mods.

In these guides, `<ModkitRoot>` means the folder containing `PAYDAY3.uproject`. Replace this placeholder with your own folder path; do not create a folder literally named `<ModkitRoot>`.

== Install the project

Open the https://github.com/PAYDAY3-Modding/PD3-Modkit[Modkit GitHub repository] to install the modkit project.

Clone the repository or fork it and clone your fork, or choose *Code > Download ZIP* and extract the project to a writable development directory.

image::installmodkit-navigation.png[Modkit repository with the Code menu open and Download ZIP visible, width=800]

[WARNING]
====
Downloading the project as a ZIP may cause issues with the modkit updater. Cloning the repository or your fork is recommended.
====

Avoid placing the project inside the PAYDAY 3 installation directory.

== Complete the Wwise `ThirdParty` setup

Before building or opening the modkit, complete xref:wwise-setup.adoc[Set Up Wwise].

The modkit contains a modified Wwise integration based on *Wwise 2023.1.15.8789.3579*, but the Audiokinetic SDK libraries and other non-text `ThirdParty` files are not distributed with it.

Copy the required `include` and matching Windows `x64_*` SDK folders from your Wwise 2023.1.15 installation into:

[source,text]
----
<ModkitRoot>\Plugins\Wwise\ThirdParty\
----

Do not replace the bundled modified Wwise plugin with the stock Audiokinetic integration. Only restore the missing `ThirdParty` SDK payload as described on the Wwise setup page.

[IMPORTANT]
====
The modkit does *not* include a generated JMAP.

After downloading the modkit, there are two separate pieces of game data that must be refreshed for your installed PAYDAY 3 version:

* `AssetRegistry.bin`, which is extracted from the game and placed in the modkit root so the editor can discover and load cooked PAYDAY 3 assets.
* The JMAP, which is dumped from a clean running PAYDAY 3 process by `GenerateJMAP.bat` and is then used by Suzie to generate the modkit's native class stubs.

`AssetRegistry.bin` is *not* an input to `GenerateJMAP.bat`.
====

== Add the current `AssetRegistry.bin`

Complete xref:fmodel-setup.adoc[Set Up FModel] first. FModel must have the PAYDAY 3 AES key and a current local mappings file configured so it can reliably read the game archives.

Open FModel with your PAYDAY 3 installation selected, locate the game's `AssetRegistry.bin`, and export the file using FModel's raw file export/save functionality.

image::assetRegistry-location.png[AssetRegistry.bin beside PAYDAY3.uproject in the modkit root folder, width=800]

Copy the extracted file to the root of the modkit:

[source,text]
----
<ModkitRoot>/AssetRegistry.bin
----

The editor uses this asset registry to know which cooked PAYDAY 3 assets exist and which cooked packages it can resolve and load through the modkit's cooked-asset workflow.

[NOTE]
====
`AssetRegistry.bin` is an asset catalogue used by the editor. It is separate from both the FModel `.usmap` mapping file and the modkit JMAP.
====

You do not need to extract the game's cooked assets into the modkit `Content` directory. The editor references the installed game's cooked content rather than requiring redistributed copies of those assets.

Make sure `AssetRegistry.bin` comes from the same PAYDAY 3 version that you intend to mod.

== Generate the JMAP

The JMAP is generated from the *running game*, not from `AssetRegistry.bin`.

Do this after downloading or updating the modkit, and repeat it after PAYDAY 3 updates so the reflected native game data stays in sync with the installed game version.

=== 1. Prepare a clean PAYDAY 3 installation

Before generating the JMAP, temporarily remove or disable all PAYDAY 3 mods and UE4SS.

The JMAP should be dumped from an unmodified PAYDAY 3 process so the generated reflection data represents the stock game rather than classes or objects introduced or altered by runtime mods.

[WARNING]
====
Do not generate the JMAP while UE4SS or other mods are installed and active in PAYDAY 3.
====

=== 2. Start PAYDAY 3

Launch PAYDAY 3 with the clean setup and leave the game running.

`GenerateJMAP.bat` works against the live PAYDAY 3 process and runs the JMAP dumper on the running game.

=== 3. Run `GenerateJMAP.bat`

With PAYDAY 3 running, run:

[source,text]
----
GenerateJMAP.bat
----
image::runBat-RUNIT.png[File Explorer with GenerateJMAP.bat highlighted in the modkit root folder, width=800]

Follow any prompts printed by the script while it connects to the running game and dumps the current JMAP.

*Check:* After the script finishes, confirm that a `.jmap` file is present in `<ModkitRoot>/Content/DynamicClasses/`. If it is missing or the script reports an error, keep the clean game running, check the script's error message, and rerun it before opening the project.

[NOTE]
====
The generated JMAP is local generated data. It is not included with the modkit download, so this step must be completed on a new modkit installation before the current reflected game data is available.
====

== Run `JukeboxSetup.bat`

Before opening the project, run `JukeboxSetup.bat` from `<ModkitRoot>`, alongside the `GenerateJMAP.bat` setup step.

The script downloads or updates JukeboxMod in `<ModkitRoot>/Mods/JukeboxMod`. For a Git clone, it initializes the modkit's submodules and updates JukeboxMod. For a ZIP download, it clones JukeboxMod directly instead.

. Make sure Git for Windows is installed and available in `PATH`, even if you downloaded the modkit as a ZIP. The script needs an internet connection to download or update the files.
. In the folder containing `PAYDAY3.uproject`, double-click `JukeboxSetup.bat`.
. Wait for the script to report `Setup completed successfully.`, then press a key to close it.

image::jukebox-setup-location.png[JukeboxSetup.bat alongside GenerateJmap.bat and PAYDAY3.uproject in the modkit root folder, width=400]

*Check:* Confirm that `<ModkitRoot>/Mods/JukeboxMod` contains the downloaded mod files. If the script reports `Setup failed`, resolve the error shown and rerun it before opening the project.

== Starting the Project

After installing the Wwise SDK, generating the JMAP, adding the current `AssetRegistry.bin`, and successfully running `JukeboxSetup.bat`, open `PAYDAY3.uproject` with the custom editor.

Unreal Engine will create local folders and may generate `PAYDAY3.sln`, the Visual Studio solution file, in the modkit root.

If you see the following error after copying the Wwise SDK files into `Plugins/Wwise/ThirdParty/`, build the project as described below:

* Plugin 'Wwise' failed to load because module 'Wwise' could not be found.  Please ensure the plugin is properly installed, otherwise consider disabling the plugin for this project.

Open `PAYDAY3.sln` in Visual Studio 2022 version 17.8 or later with the C++ toolchain installed. If needed, install Visual Studio and the required C++ tools first:

https://dev.epicgames.com/documentation/unreal-engine/setting-up-visual-studio-development-environment-for-cplusplus-projects-in-unreal-engine

[NOTE]
====
If `PAYDAY3.sln` is missing, right-click `PAYDAY3.uproject`, choose *Show more options*, then select *Generate Visual Studio project files*.

If this command is missing, follow xref:install-editor.adoc#_generate_project_files_without_the_context_menu[Generate project files without the context menu]. That method uses the custom engine directly and does not require Epic Games Launcher or UnrealVersionSelector. The same page explains how to restore the menu when your release includes the selector.
====

In Visual Studio, select *Build > Build Solution*.

Wait for the build to finish. It should take about 3–5 minutes.

Once the output reports a successful build, open the project again.

*Check:* The project should open in the custom editor without the Wwise module error. Configure the game paths on the next page before checking for game assets in the Content Browser.


== Expected components

A complete development setup includes the PAYDAY 3 project/stubs and the required modding plugins, including CrimeFactory and Suzie.

Depending on the distribution, compiled plugin binaries may already be supplied. Source-based setups may require a project/plugin build before the editor can open successfully.

== Do not copy game assets into the project

[WARNING]
====
Do not populate the project by extracting PAYDAY 3 cooked assets into `Content`.

The cooked-asset workflow uses the user's installed PAYDAY 3 content as read-only reference data. Your project should contain modkit content and assets you own or are permitted to redistribute.
====
