= Reflected Game Types

PAYDAY 3 assets frequently depend on native game classes that do not exist in a normal Unreal project.

The modkit uses a JMAP and Suzie so those native PAYDAY 3 classes can be exposed automatically in the editor without requiring users to regenerate UHT headers manually.

== Generate the JMAP

`GenerateJMAP.bat` runs the JMAP dumper against a clean running PAYDAY 3 instance.

It does not use `AssetRegistry.bin`.

The generated `.jmap` used by the modkit must be present under:

[source,text]
----
<ModkitRoot>/Content/DynamicClasses/
----

See xref:getting-started:install-modkit.adoc[Install the Modkit] for the clean-game requirements when generating it.

== What Suzie does

Suzie runs when the project starts.

On startup it:

. Reads the JMAP from `Content/DynamicClasses`.
. Generates the native PAYDAY 3 runtime classes represented by that JMAP.
. Registers those classes so they can be referenced and used in the editor.

This gives mod authors access to native PAYDAY 3 class types that are required by content such as Data Assets, Blueprint parents, and many other game assets.

== Generated files are local

The runtime classes generated by Suzie are local-only generated data.

They are not committed to the modkit repository.

Suzie regenerates them whenever the project starts, using the JMAP currently present in `Content/DynamicClasses`.

Because of this, the JMAP is the important versioned input to keep current after PAYDAY 3 updates.

== UE4SS UHT generation is not required

[IMPORTANT]
====
Do not run UE4SS UHT generation as part of normal PAYDAY 3 modkit setup.

Suzie and the JMAP provide the native-class generation workflow used by the modkit.
====

UE4SS can still be useful for other runtime inspection, dumping, or reverse-engineering tasks, but its UHT generator is not part of this modkit pipeline.

== Relationship to AssetRegistry.bin

`AssetRegistry.bin` and the JMAP are separate inputs:

[cols="1,3"]
|===
|Input |Purpose

|`AssetRegistry.bin`
|Tells the editor which PAYDAY 3 cooked assets exist and should be exposed from the mounted game content.

|JMAP
|Provides the reflected native PAYDAY 3 type information that Suzie turns into runtime classes for the editor.
|===

Both need to match the version of PAYDAY 3 the modkit is targeting.

== Add editor behaviour to generated classes

Suzie can attach custom C++ function bodies and automatic editor callbacks to the classes it creates from the JMAP. You can use this to implement existing reflected functions or react to object and property events without recreating the original game class.

See xref:suzie-native-bodies.adoc[Suzie Native Bodies API] for the supported macros, Context methods, value types, and Editor-only limitations.
