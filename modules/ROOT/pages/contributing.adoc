= Contributing
:page-documentation-contributors:

Documentation contributions are welcome.

== Before writing

Read the repository `README.md` for the project-wide writing rules.

The most important rule is simple: document what the toolchain actually does today.

Do not turn assumptions, planned features, reverse-engineering hypotheses, or unverified paths into instructions.

== Page style

A task page should normally contain:

. A short explanation of what the task accomplishes.
. Prerequisites.
. Numbered steps.
. The expected result.
. Relevant warnings or known limitations.
. Links to deeper reference material.

Use `NOTE`, `TIP`, `IMPORTANT`, `CAUTION`, and `WARNING` blocks when the information belongs directly beside a procedure.

=== Optional technical detail

Put technical information that is not immediately needed to complete the task in a collapsible section (a dropdown). This keeps the main instructions easy to follow while letting readers open the extra detail when they need it.

Use a clear title that explains what the section contains:

[source,asciidoc]
----
.How this works internally
[%collapsible]
====
Additional technical explanation goes here.
====
----

Keep required steps, prerequisites, and warnings needed to complete the task visible outside the dropdown. Link to a separate technical reference page when the explanation needs more space.

== Images

Put images in the `images` family of the module that owns the page.

Reference them using Antora resource IDs rather than filesystem-relative paths.
